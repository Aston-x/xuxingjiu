# 常见坑

都是真踩过的。每条按「现象 → 根因 → 怎么办」写。

---

## 一、运维类

### 1. 每次都要重新登录 QQ

**现象**：关一次机器人，自己 QQ 就掉线了。

**根因**：用了 `taskkill /IM QQ.exe` 或类似的按镜像名杀进程 ——
你的日常 QQ 与 NapCat 注入的机器人号是**同一个 `QQ.exe`**（同一份安装、同一个进程）。

**怎么做**：永远不要按镜像名杀 QQ。`launcher.py` 停进程时一律**按端口定位**，
再核对进程镜像名（`EXPECT` 表），QQ 根本不在候选里。
需要"干净地重来"时，手动关掉那个 QQ 窗口再双击启动即可。

### 2. 环境变量里的代理把本机请求打死

**现象**：本地 LM Studio 明明开着，但请求超时 / 连不上；外网 API 正常。

**根因**：系统里设了 `HTTP_PROXY` / `HTTPS_PROXY`，`httpx` 默认 `trust_env=True`，
于是连 `127.0.0.1` 的请求也被塞进代理。

**怎么做**：框架已经处理 —— `127.0.0.1` / `localhost` / `::1` / `0.0.0.0` 上的端点
强制 `trust_env=False`。**局域网推理机**（`192.168.x.x`）不在这个名单里，
要显式写 `"trust_env": false`。

### 3. `reg.exe` / `sc.exe` / `schtasks.exe` 被拦

**现象**：NapCat 的 `launcher-user.bat` 报 `provided QQ path is invalid`；脚本改服务失败。

**根因**：部分受限环境（企业策略 / 安全软件 / 沙箱）把这三个程序当 LOLBin 拦掉。
上游 NapCat 的启动器**硬依赖 `reg.exe` 读注册表**。

**怎么做**：用本项目的 `launcher.py`（走 Python `winreg`，不受限制），
或设环境变量 `QQ_EXE` 指向 QQ 安装路径，再走 `NapCat/launcher.example.bat`。

### 4. 无 BOM 的 UTF-8 脚本里中文路径失效

**现象**：`.ps1` / `.bat` 里写中文路径，运行时报"找不到路径"。

**根因**：Windows 上无 BOM 的 UTF-8 脚本会被按 GBK 解析。

**怎么做**：把脚本存成**带 BOM 的 UTF-8**，或干脆避免在脚本里写中文路径
（用变量 + `%~dp0` 推导）。

### 5. 批量替换把文件改坏

**现象**：做过一次全库替换后，配置文件/代码出现莫名其妙的错误。

**根因**：替换前没备份；或者把"数组的数组"传给某个封装函数，导致参数被扁平化
（曾经因此把文件里所有 `D` 换成 `:`）。

**怎么做**：**批量替换前先备份**，替换规则逐条写清楚、替换后立刻做语法体检。
本项目里的做法见 `test_regression.py` 开头的状态隔离 + 结尾的污染自检。

## 二、模型接口类

### 6. 报 400 但看不出原因

**现象**：`HTTPStatusError 400`，日志里没有服务端原话。

**怎么做**：框架在 `transport.send()` 里已经做了 —— 4xx/5xx 会先把
`resp.text[:400]` 打进日志再抛错。看不到就去控制台「日志」页搜 `模型接口`。

### 7. 换了厂商之后缓存命中率恒为 0

**根因**：各家的 usage 字段名不同（DeepSeek 是 `prompt_cache_hit_tokens`，
OpenAI 是 `usage.prompt_tokens_details.cached_tokens`，Anthropic 是
`cache_read_input_tokens`，Gemini 是 `usageMetadata.cachedContentTokenCount`）。
不映射就永远是 0。

**怎么做**：在端点或清单里写 `usage` 映射。内置清单已经配好了常见厂商。

### 8. 把某家的私有参数发给了别家

**现象**：Groq / OpenRouter / Kimi 返回 400，说未知字段。

**根因**：`thinking` 这类参数只有 DeepSeek 认。它**不能**写进通用 body。

**怎么做**：私有参数写在**端点级** `params` 里：

```jsonc
{"id": "ds", "provider": "deepseek", ..., "params": {"thinking": {"type": "disabled"}}}
```

### 9. base_url 到底要不要带 `/v1`

**答案**：**按厂商文档原样写，框架不自动补**。

- DeepSeek：`https://api.deepseek.com`（不带 `/v1`）
- Kimi / OpenAI / 硅基流动：`https://api.xxx.com/v1`（带）
- LM Studio：`http://127.0.0.1:1234/v1`

曾有人想"智能补 `/v1`"，结果是两种写法行为分叉 + 本地端点被污染。

### 10. 回复被截断，翻倍重试反而必然失败

**根因**：`max_tokens` 的字段名与上限各家不同（`max_tokens` /
`max_completion_tokens` / `generationConfig.maxOutputTokens` /
`options.num_predict`）。翻倍时不夹上限会被服务端 400 顶回来。

**怎么做**：给端点声明 `capabilities.max_tokens_limit`，框架会
`min(翻倍值, 上限)`。

### 11. 温度越界导致 400

比如 Kimi 的温度上限是 1，传 1.7 会被拒。框架按 `temperature_range`
**静默夹紧**并记 debug 日志，不会透传报错。MiniMax 的下限是 0.01，同理。

### 12. 看不到图时她编造图里的内容

**根因**：图片占位措辞与后端能力不一致 —— 后端明明能看图，占位却说"你看不到"，
系统提示词和这条占位互相打脸，她只能编。

**怎么做**：`providers/base.py` 里那两句措辞是**反幻觉关键**：

- 后端能看图、只是这条通道传不了图 → `VISION_PLACEHOLDER_NO_CHANNEL`
- 后端本身看不了图 → `VISION_PLACEHOLDER_BLIND`

`test_regression.py` 【31】段对它们有逐字断言，改之前先看测试。

### 13. 改了 api_key / 并发数不生效

**根因**：配置改了但没重载 —— 端点对象、密钥、信号量都是按配置算出来的。

**怎么做**：走面板改会自动重载；手工改文件请重启进程。
自己写代码调配置时记得 `ROUTER.reload(cfg)`。

### 14. 插件加载失败把整个进程拖垮了

**怎么做**：框架已经保证不会 —— 每个插件独立 `try/except BaseException`，
失败只记进 `errors`。另外**默认不扫目录**（`allow_dir_scan: false`），
只加载 `enabled` 白名单里点名的文件。

**但请注意**：插件是**主进程内执行**，没有真沙箱。别人的插件先看代码再启用。

## 三、状态与数据类

### 15. 跑一次测试就把真实数据写坏了

**根因**：测试直接调用了会 `save()` 的单例方法，而它们的 `path` 还指着真实文件。

**怎么做**：`test_regression.py` 的做法值得抄 —— 开跑前把所有可写路径
（`config.json`、`memory.json`、`mood.json`、`state/` 下各项……）**一次性重定向**到
`_tmp_iso/`，结尾再做一次**指纹自检**（大小 + mtime）证明真实文件没被动过。

### 16. 上下文里留着图片，之后连续好多轮都失败

**根因**：不支持视觉的端点收到 `image_url` 会 400，而图片还留在上下文里，
于是每一轮都带着它去撞墙。

**怎么做**：`Provider.prepare_messages()` 在**发出去之前**就把图片段换成文字占位，
不是等报错再补救。

### 17. `config.json` 被提交到仓库里了

**怎么做**：`.`gitignore` 里已经有 `config.json`。真提交过就用
`git rm --cached config.json` 撤出索引，**并且立刻轮换里面出现过的所有密钥**
（提交过就等于泄露过，改 `.gitignore` 不能挽回）。
