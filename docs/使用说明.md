# 许杏玖 · 使用说明

面向使用者（不是开发者）。装还没装好？先看 [部署.md](部署.md)。
要改模型接口？看 [providers.md](providers.md)。

---

## 一、日常只需要认三个文件

| 文件 | 干什么 |
| --- | --- |
| `qqbot\启动.pyw` | 双击 = 启动（补齐缺失的组件，绝不杀进程） |
| `qqbot\停止.pyw` | 双击 = 停止机器人（**不动 QQ**） |
| `qqbot\打开控制台.pyw` | 双击 = 打开面板（自动带令牌，不用手输） |

三个都是 `.pyw`，所以**不会弹黑窗口**——它们由 `pythonw.exe` 运行，
日志全部落在文件与控制台里，不会在桌面上刷屏。

命令行等价物：

```bat
cd qqbot
.venv\Scripts\python.exe launcher.py start     :: 或 stop / status
```

## 二、第一次用

1. **双击 `qqbot\启动.pyw`**。它会依次补启 qqbot → 空间桥 → NapCat，
   每一步先探测端口再动手；已经在跑的直接跳过。
2. **等浏览器自动打开面板**（默认 <http://127.0.0.1:6200/>）。
3. **在面板上看一眼状态**：
   - 「识图」块：能看到后端（自动 / 只走云端 / 只走本地）与本地模型探测结果；
   - 「日志」页：搜 `用量 入`，有记录说明模型链路通了；
   - 「提示词」页：她当前拿到的完整系统提示词——**调人设时最有用的一个页面**。

第一次启动 QQ 可能停在登录界面，这时请自己双击 `NapCat\launcher-user.bat`
完成登录（那个窗口有界面，能看到 QQ 的提示）。**不要反复重启，更不要杀 QQ 进程。**

## 三、控制台里有什么

面板是**只读为主**的：大部分块只展示状态，只有少数组件能改配置。
能改的项都会即时写回 `config.json` 并同步内存，不需要重启。

| 块 | 你能看到 / 能做什么 |
| --- | --- |
| 概览 | 运行时长、token 累计、当前作息状态、待办 |
| 日志 | 实时日志（带密钥脱敏），可切换来源（bot / 空间桥 / NapCat） |
| 提示词 | 她当前拿到的系统提示词（调人设必看） |
| 识图 | 后端选择、本地模型探测结果（加载了哪个模型、上下文多长）、识图统计；**可切换后端** |
| 模型端点 | 每个端点的 id / 类型 / tier / 是否有密钥 / 是否可用 / 探测结果（新增，因为端点不再是写死的两个） |
| 开关 | 各项功能的开 / 关（写回配置） |
| 话术与列表 | 唤醒前缀、兜底台词等列表类配置 |
| 好感 / 心情 | 某人在她心里的档位与心情曲线 |
| 表情包 | 收藏的表情包（按场景挑） |
| 出图 | 生成的图片产物 |

**令牌**：面板需要令牌，`打开控制台.pyw` 会自动带上。
手工访问时令牌在 `qqbot\state\console-token`。忘了就删掉那个文件重启，
会重新生成一个。

## 四、她能做什么

### 聊天

- **群里**：不是每句都回。被 `wake_prefix` 喊到（默认「许杏玖」「玖玖」之类）
  或直接 @ 她，回复率接近 100%；其余时候按活跃度排队，**大多数消息她会装没看见**
  —— 这是刻意的，不然就是个复读机。
- **私聊**：基本都会回。
- 回复短、口语化、不用书面语，会主动反问。

### 她有自己的生活

她**不是随叫随到的工具**。`config.json` 的 `life.schedule` 是她的作息表
（几点醒、下午在旧书店、夜里最精神），`self_activity.acts` 是她自己在做的事
（翻旧书 / 趴窗台 / 盯虫子 / 舔毛……）。

于是会出现这些行为：

- 忙的时候（在上班、在睡觉）会**延迟回复**，而不是秒回；
- 心情不好时回复更冲；
- 群里冷场久了，她可能**自己冒一句**；
- 每隔一段时间她会往管理员私聊发一条**活动报告**（今天干了什么、跟谁聊了）。

调参入口都在面板的「开关」与「话术与列表」里。

### 记忆

分三层，按 QQ 号跨群与私聊共享：

| 层 | 记什么 | 上限 |
| --- | --- | --- |
| 人物记忆 | 某人是谁、性格、说过的事、待办 | 12 人 × 5 条特征 × 3 条待办 |
| 群记忆 | 这个群里的约定 / 梗 | 每群 10 条 |
| 好感与心情 | 对某人的长期印象 + 短期情绪 | 见「好感 / 心情」面板 |

- **记忆内容由她自己裁量**（模型觉得值得记才记）；
- 默认 `memory.ask_admin_before_remember=true`：拿不准时会在管理员私聊里问一句；
- 冲突规则：更早的记录优先；**本人对自己说的话可以覆盖**；管理员说的话永久置顶；
- 每天凌晨 `memory.reset_hour`（默认 4 点）做一次日切，超过
  `reset_every_days` 天的短期内容会淡出。

数据在 `qqbot\memory.json` 等文件里，**不要手动改**（格式错了会导致她认不出人）。

### 识图

她**真的能看图**，而且看不到时会明说「我看不到」，不会编。

- 面板「识图」块可选后端：`auto`（云端优先，失败退本地）/ `cloud` / `local` / `off`；
- 超过上限的图会先压缩（云端与本地是两档不同的分辨率，避免白烧显存）；
- 动图只抽若干帧；
- 如果当前模型看不了图，图片会被替换成一句文字占位——**这是刻意的**，
  因为把图片留在上下文里会让之后连续好几轮调用都失败。

想要本地识图，需要一个 VL 模型（如 `qwen2.5-vl-7b-instruct`），
在 LM Studio 里加载后她会自动探测到。

### 出图

三种模式：

1. **随手画**（`[画图:想要什么]`）—— 按你的描述生成；
2. **画她自己**（`[画图:她的样子]`）—— 用固定人设（`self_image`）保证形象一致；
3. **配图**（发说说时自动带一张）。

需要有 Stable Diffusion WebUI 在 `config.json` 的 `sd` 段配的地址上运行。
**配额**：私聊每日 10 张、空间每日 1 张（可调），防止被连着刷爆显存。

### 表情包

她自己收藏表情包，并**按场景挑**——被骂时发哪个、接梗时发哪个。
`stickers.allow_image_fallback` 控制收藏用完时要不要退回问她 / 出图。

数据在 `qqbot\stickers\`。

### 活跃度与打断

- 被 @ 或喊名字 = **强制打断**，她不忙就一定理你；
- 普通消息累积「兴趣值」（`attention.threshold`），攒够了会自己搭话；
- 她在忙时只有 `life.busy_at_silent_chance` 的概率会看手机；
- 长间隔的沉默会让她主动开启话题（`quote.on_long_silence`）。

### 群管理（只有管理员能用）

| 指令 | 说明 |
| --- | --- |
| `[禁言:QQ号或昵称 分钟]` | 不写分钟 = 用 `ban.default_minutes` |
| `[跨群禁言:群名 昵称 分钟]` | 她在那个群也是管理员才会执行；有歧义就不动手 |
| `[说说:配文]` | 发一条 QQ 空间说说（受 `admin.restrict.qzone_post` 限制） |
| `[点赞:某人]` / `[评论:某人 内容]` | 空间互动 |

管理员名单在 `config.json` 的 `admin.user_ids`。
**这个列表为空时所有人都算管理员** —— 启动日志会打醒目警告，别忽略它。

安全阀：每小时 `ban.max_per_hour` 条、每天 `ban.max_per_day` 条、
同一目标 `ban.same_target_cooldown_seconds` 冷却、她自发起禁言上限更短。
`ban.protected_ids` 里的人**任何情况下都不会被禁**（记得把你自己填进去）。

### B 站

配置好后她会：扫码登录、挑视频看、点赞 / 投币 / 收藏。

- **每日总动作上限** `bili.daily_action_cap`（默认 6 次，赞/币/藏合计）；
- 掉登录会主动通知管理员；
- 浏览记录会进活动报告。

不想要就把 `bili.enable` 关掉。

## 五、常见问题

### 双击 `.pyw` 弹「系统找不到指定的文件」

多半是 `.pyw` 文件关联坏了（被指到一个不存在的解释器）。
最简单的修法：右键 `.pyw` → 打开方式 → 选 `qqbot\.venv\Scripts\pythonw.exe` 并勾选"始终"。
替代方案：在 `qqbot` 目录里跑 `python launcher.py start`。

### NapCat 窗口里中文是乱码

Windows 控制台默认代码页是 936（GBK），而 NapCat 输出 UTF-8。
不影响功能，真要看清楚就在那个窗口先敲 `chcp 65001`。

### 面板打不开

1. 先确认进程在跑（`launcher.py status`，或看 `state\bot.lock`）；
2. 端口被占：`config.json` 里 `console.port` 换个值重启；
3. 只有本机能访问（`host` 固定 `127.0.0.1`），从别的机器打不开是正常的。

### 要令牌，但我不知道是什么

令牌在 `qqbot\state\console-token`。**别直接双击 `启动.pyw` 之外的入口**——
`打开控制台.pyw` 会自动带上令牌。手工访问时把它整行粘进输入框。

### 显示「等待 NapCat」/ 收不到群消息

按顺序查：

1. qqbot 是否先在 6199 上等（日志里有 `服务已启动 ws://127.0.0.1:6199`）；
2. `NapCat/config/onebot11_<QQ>.json` 的 `url` 端口与 `token` 是否与
   `qqbot/config.json` 的 `ws_port` / `access_token` **完全一致**；
3. NapCat 里的 QQ 是否已登录（不是登录界面）；
4. `config.json` 的 `bot_qq` 是否就是登录的那个号。

### 我不小心把 QQ 关了，要重新登录大号吗

不用。**但绝对不要 `taskkill /IM QQ.exe`** —— 你的日常 QQ 和机器人号是同一个
`QQ.exe` 进程，按镜像名杀会把大号一起带走。关掉 NapCat 那个 QQ 窗口后，
双击 `启动.pyw` 重新注入即可。

### 电脑重启后要做什么

双击 `deploy\start-all.pyw`（仓库根）或 `qqbot\启动.pyw`。
第一次登录 QQ 可能要手动过一下登录界面，之后就自动了。

### 想看日志

- 控制台「日志」页（推荐，带来源切换与脱敏）；
- `qqbot\bot.log`（运行日志）、`qqbot\bot_boot.log`（启动日志）、
  `qqbot\launcher.log`（启动器日志）。

日志里的密钥会被自动替换成 `***`（`console_server.py` 里的脱敏表）。

### 她回复很慢 / 老是「稍后回你」

先看她是不是"忙"——面板「概览」有当前作息状态。
如果是本地模型：`local.timeout_seconds` 太小、或模型上下文被别的程序挤爆都会慢。
云端慢就换端点，或把 `chains.default` 改成云端优先。

### 她编造没发生过的事

三种可能：

1. **记忆文件被手工改坏了** —— 用面板「好感 / 心情」核对一下是不是真记错了；
2. **图片占位措辞与后端能力不一致** —— 别去改 `providers/base.py` 里那两句措辞，
   它们是反幻觉的关键，改错她会把识图拿到的描述也一起否认掉；
3. **模型太弱** —— 换一个，或把 `max_context_turns` 调小。

## 六、命令行 / 高级用法

```bat
:: 启动 / 停止 / 状态
.venv\Scripts\python.exe launcher.py start|stop|status

:: 全量回归（不联网、不碰真实状态文件）
.venv\Scripts\python.exe test_regression.py

:: 模型层单测（纯离线）
.venv\Scripts\python.exe test_providers.py

:: 把缺失的配置项按默认值补回来（幂等，只加不改）
.venv\Scripts\python.exe tools\ensure_config.py --check

:: 看看她实际拿到什么提示词（调人设时很有用）
.venv\Scripts\python.exe tools\dump_prompts.py

:: 采样一批回复，判断人设是否跑偏
.venv\Scripts\python.exe tools\sample_replies.py

:: 探一下本地模型到底加载了什么、上下文多长
.venv\Scripts\python.exe tools\vision_probe.py
```

### 聊天里能用的命令（管理员）

人设管理走 `/人设`（受 `admin.restrict.persona` 管，默认只有管理员能用）：

```
/人设              看这个会话用的哪张卡、卡库里都有什么
/人设 换 <卡id>     这个会话换成那张卡（群聊里就是给这个群换）
/人设 默认          这个会话改回默认卡
/人设 全局 <卡id>   改默认卡（没单独设过的地方都跟着变）
/人设 退位          把 config.json 里还压着角色卡的老键删掉，改成以卡为准
```

每个会话可以有自己的角色卡：群里绑的就是这个群，私聊绑的就是这段私聊。

角色卡放在 `qqbot/personas/<卡id>.json`，一张卡就是一个角色的全部设定（人设、世界观、
语气、话术池、生图形象）。想加一个角色就复制一份改内容；卡 id 用字母数字和短横线。

**硬约束**：`config.json` 里 `persona_lock` 打开时，她的名字和长相
（`name` / `aliases` / `self_image` / `character_tags`）谁都改不了，能改的只有
"她怎么说话"；关掉它（开源版默认关着）就什么都能改 —— 换个人就是换个角色。

## 七、为什么搬盘不用改代码

`launcher.py` 与 `bot.py` 找同伴目录的方式是「**看自己所在的上一级**」：

```
<仓库根>/
├── qqbot/          ← 从这里的上一级找下面两个
├── qzone-bridge/
└── NapCat/
```

所以整体搬到别的盘、把仓库根改个名，都不需要改代码。
实在找不到时才会退回使用配置里的兜底路径。

QQ 的安装路径也是这个思路：优先环境变量 `QQ_EXE`，其次注册表，
最后才试几个常见位置。换机器时不需要改脚本。
