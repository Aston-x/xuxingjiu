# 部署：从零跑起来（Windows）

面向**完全没接触过这个项目**的人。跟着走一遍大概 20 分钟，其中大半时间在下载。

全程只需要三样东西：Python、Node.js（只想聊天可以不装）、NapCat（第三方）。

---

## 0. 先搞清楚你要什么

| 目标 | 需要装 |
| --- | --- |
| 只想让她在群里聊天 | Python + NapCat |
| 还想让她刷 B 站、发说说、看好友动态 | 上面 + Node.js + qzone-bridge |
| 还想让她画图 | 上面 + Stable Diffusion WebUI（独立项目） |

先按第一行跑通，再逐步加。**别一开始就全上** —— 出问题时分不清是哪一层。

## 1. 环境

- Windows 10 / 11
- Python **3.11+**（[python.org](https://www.python.org/downloads/)，安装时勾上 "Add to PATH"）
- 一个**专门给机器人用**的 QQ 号（别用日常号 —— 见第 5 节）
- QQ 客户端（NT 版，即 QQNT）

> 为什么强调"专门给机器人用的号"：NapCat 是注入式框架，会 hook QQ 客户端。
> 用日常号一旦被风控，影响的是你的主账号。

## 2. 装机器人主体

```bat
cd qqbot
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
copy config.example.json config.json
```

然后打开 `config.json`，**至少要改这两处**：

```jsonc
{
  "bot_qq": 10001,                          // ← 改成你的机器人 QQ 号
  "access_token": "",                       // ← 自己编一个随机串，后面 NapCat 要填一样的
  "admin": { "user_ids": [10002] },         // ← 改成你自己的 QQ 号
  "ban":   { "protected_ids": [10002] }     // ← 同上，豁免名单
}
```

> `access_token` 是 qqbot 与 NapCat 之间的握手凭证，不是任何平台的 API Key，
> 随便编一串 12 位以上的随机字符就行（**但两边必须一致**）。

### 2.1 配模型

模型接口在 `config.json` 的 `providers` 段，出厂自带两个端点（本地 LM Studio + 云端 DeepSeek）。
**只留一个也能跑**，把不用的那个 `enabled` 设成 `false` 即可。

最简单的方案是只用云端：删掉或禁用 `local-lmstudio` 那个端点，然后：

```bat
setx DEEPSEEK_API_KEY "sk-你的密钥"
```

（`setx` 写的是用户级环境变量，**新开的终端**才生效。别把密钥直接写进 config.json。）

换其他厂商、加多个端点、配回退链 —— 见 [providers.md](providers.md)。

### 2.2 先单独验证她能说话

```bat
.venv\Scripts\python.exe bot.py
```

看到 `服务已启动 ws://127.0.0.1:6199 (等待 NapCat 反向连接)` 就对了。
此时还没接 QQ，所以不会有消息进来。

## 3. 装 NapCat 并接上

见 [`NapCat/README.md`](../NapCat/README.md)。要点：

1. 从上游 Release 下载 Windows 一键包，解压到 `NapCat/`；
2. 把 `NapCat/config/` 下的三个 `.example.json` 复制成正式文件，
   **文件名里的 `<QQ号>` 换成你的机器人号**；
3. 在 `onebot11_<QQ>.json` 里把 `url` 与 `token` 和 `config.json` 对齐：

```jsonc
"url": "ws://127.0.0.1:6199/ws",   // 端口 = config.json 的 ws_port
"token": "你刚才编的那串",           // 必须与 config.json 的 access_token 一致
```

## 4. 启动

推荐**双击** `deploy\start-all.pyw`（无黑窗口，自动按顺序拉起 qqbot → 空间桥 → NapCat）。

它做完之后会自动打开控制台：<http://127.0.0.1:6200/>
（令牌在 `qqbot/state/console-token`，`打开控制台.pyw` 会自动带上）。

### 验证清单

| 检查项 | 怎么看 |
| --- | --- |
| qqbot 在跑 | 控制台能打开，端口 6199 有监听 |
| 模型可用 | 控制台「日志」页搜 `用量 入` —— 有记录说明调通了 |
| NapCat 连上了 | 日志里出现连接建立；或 `状态.py` 看到 6199 被 python 占用、QQ.exe 在跑 |
| 能收消息 | 用你自己的号给她发一句，日志里会出现你的 QQ 号 |
| 权限对 | 用管理员号发 `[禁言:某人 1]`，能生效说明 `admin.user_ids` 填对了 |

⚠️ **第一次启动 QQ 可能停登录界面** —— NapCat 注入后需要你手动登录机器人号。
这时请自己双击 `NapCat\launcher-user.bat`（有窗口，能看到 QQ 的提示），
**不要**反复重启，也不要杀 QQ 进程。

## 5. 装空间桥（可选）

```bat
cd qzone-bridge
npm install
copy .env.example .env
```

`.env` 里需要填 QQ 空间的 Cookie。**这一步请用你自己的号**（机器人号通常没开通空间权限）：

- 浏览器登录 QQ 空间 → F12 → Network → 随便点一个请求 → 复制 Cookie 字符串；
- 或者设 `QZONE_ENABLE_QR=1`，启动后扫码。

Cookie 是**账号级凭据**，等同于账号密码。`qzone-bridge/.gitignore` 已经挡了 `.env`，
但请不要再复制到别处。

详细步骤见 `qzone-bridge/README.md`。

## 6. 目录最终形态

```
<仓库根>\
├── qqbot\              ← 主体（config.json 在这里，不要提交）
├── qzone-bridge\       ← 空间桥（.env 在这里，不要提交）
├── NapCat\             ← 第三方本体 + config
└── deploy\             ← 一键启动
```

`qqbot/launcher.py` 是按"三个目录平级"这个假设找兄弟目录的，
所以**整体搬到别的盘、改目录名都不需要改代码**。

## 7. 出问题了去哪看

1. 控制台的「日志」页 —— 90% 的问题这里能直接看到原因（密钥错误、连接失败、模型 400）；
2. `qqbot/bot_boot.log`、`launcher.log` —— 启动阶段的问题；
3. [`常见坑.md`](常见坑.md) —— 踩过的坑与现象对照表。

如果日志里出现 `模型接口 ... 返回 400/401`，先去 [providers.md](providers.md#6-常见坑)
对一遍，多半是 base_url 写错或者把某家的私有参数发给了别家。
