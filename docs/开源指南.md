# 开源指南：怎么把这个项目发布出去

从「本地一个目录」到「别人能搜到、能装、能提 issue」的全过程。
按顺序做，每一步都有**可验证的完成标志**。

> 本文是**本项目专用清单**；与项目无关的通用分步教程见 [GitHub-开源教程.md](GitHub-开源教程.md)。

> 本文假设你用的是 **GitHub**（主），末尾附 Gitee 镜像与国内加速的做法。

## 0. 发布前第一件事：密钥与隐私自查

**先做这一步，再考虑建仓库。** 提交过的密钥等于泄露过 —— 删文件救不回来。

### 0.1 扫当前工作区

```bash
cd <项目根>

# ① 密钥类
grep -rInE "sk-[A-Za-z0-9_-]{20,}" . 2>/dev/null | grep -v node_modules
grep -rInE "(api_key|apikey|access_token|secret|password)\s*[:=]\s*[\"'][^\"']{16,}" . 2>/dev/null | grep -v node_modules

# ② Cookie / 登录态
grep -rInE "skey=|p_skey=|superkey=|SESSDATA=|bili_jct=" . 2>/dev/null | grep -v node_modules

# ③ 个人标识
grep -rInE "\b[0-9]{9,11}\b" . 2>/dev/null | grep -v node_modules | head -40   # 疑似 QQ 号
grep -rInE "Users[\\\\/][A-Za-z]+|/home/[a-z]+" . 2>/dev/null | grep -v node_modules

# ④ 不该在仓库里的文件名
git status --short | grep -E "config\.json|\.env$|_state\.json|memory\.json|\.log$"
```

**完成标志**：上面四条都以「无输出」或「只有示例占位值」结束。

### 0.2 扫 git 历史

```bash
git log --all -p -- . | grep -nE "sk-[A-Za-z0-9]{20,}|skey=|SESSDATA=" | head
git log --all --name-only --pretty=format: | sort -u | grep -E "config\.json|\.env$|memory\.json"
```

如果历史里有：
1. **先吊销**那个密钥 / 退出那个登录（**这一步不能省**，改历史不能让它失效）；
2. 再用 [`git filter-repo`](https://github.com/newren/git-filter-repo) 清：

```bash
git filter-repo --path qqbot/config.json --path qzone-bridge/.env --invert-paths
# 或者把某个字符串全局替换掉。**必须写成真实文件** ——
# Windows / Git Bash 下 `--replace-text <(echo ...)` 会直接报
# FileNotFoundError: /proc/.../fd/63（实测）：
printf 'sk-真实密钥==>REDACTED\n' > /tmp/replacements.txt
git filter-repo --replace-text /tmp/replacements.txt
```

> **本仓库的历史已经清过一遍，别让它脏回去。** 第一个提交（`feat: 许杏玖 1.0 —— 开源发布首个版本`）
> 里原本带着两个真实 QQ 号、一个真实相册标识、一个真实 p_skey 和一个设备号，都是抓包样本
> 直接进测试夹具时漏掉的。首次推送到 GitHub 之前用 `git filter-repo --replace-text` 全历史
> 换成了合成值（`110000001x` / `用户甲…癸`），并且把提交身份改成了 GitHub 账号，
> 因为 `git log -p` 会把 Author 行一起打出来。
>
> 现在 `bash tools/preflight.sh` 的「git 历史」那一段会守这几条，CI 的 secret-scan 也守一份。
> 哪天它红了，配方就在 `tools/preflight.sh` 末尾打印（它连踩过的坑都写在里面：filter-repo
> 会删掉 origin、清空的提交会被剪掉、清完只能 `--force` 不能 `--force-with-lease`）。
> 改完必须复核两条：`git log --all -p | grep -nE '真实值'` 无输出，`bash tools/preflight.sh` 全绿。

### 0.3 「绝不能提交」清单

```
qqbot/config.json            明文 api_key / access_token
qqbot/state/                 控制台令牌、天气快照、生图配额
qqbot/*_state.json           sd / life / qzone 状态
qqbot/{memory,mood,groups,group_memory,qzone_comment_state}.json   个人与第三方隐私
qqbot/bili_state.json        B 站 SESSDATA（可直接操作账号）
qqbot/*.log                  运行日志（含 QQ 号与群号）
qqbot/generated/  stickers/  生图产物与收藏的表情包
qzone-bridge/.env            QQ 空间完整 Cookie
qzone-bridge/test_cache/     抓包轨迹 + 真实好友列表
NapCat/ 本体与 config/       第三方二进制 + 含 QQ 号的配置
```

这些都已经写进 `.gitignore`。**你要做的是别用 `git add -f` 绕过去。**

完成标志：`git status --ignored --short | grep '^!!'` 里能看到上述文件都被忽略。

## 1. 建仓库并首次推送

### 1.1 先在 GitHub 上建空仓库

- **名字**：`xuxingjiu`（或你喜欢的名字）
- **描述**：一句话说清是什么。例：
  `一个带人设、记忆与独立生活轨迹的 QQ 机器人（NapCat + OneBot v11），模型接口可插拔`
- **Topics**（标签，影响被搜到）：`qqbot` `onebot` `napcat` `chatbot` `llm` `persona` `python`
- **不要**勾选 "Add a README / .gitignore / license"（本地已经有了，勾了会冲突）

### 1.2 本地推送

```bash
cd <项目根>
git add -A
git commit -m "feat: 首个公开版本"          # 如果还没提交过
git branch -M main                          # 统一主干名
git remote add origin https://github.com/<你的用户名>/xuxingjiu.git
git push -u origin main
```

> 用 SSH 更省事（不用每次输密码）：`git remote add origin git@github.com:<你>/xuxingjiu.git`

### 1.3 首次推送后立刻做的三件事

1. **设置分支保护**（Settings → Branches → Add rule）：
   - Branch name pattern: `main`
   - 勾 `Require a pull request before merging`（自己一个人开发也建议勾，防止误 force push）
   - 勾 `Require status checks to pass`（CI 绿了才能合）
2. **打开 Issues**（Settings → Features → Issues 通常默认开）
3. **加仓库话题标签**（首页右上齿轮 → Topics），上面那串直接贴

完成标志：刷新仓库首页能看到 README 渲染出来、有 Topics、CI 在跑。

## 3. CI 会替你守什么

三个 workflow：

| 文件 | 干什么 | 为什么重要 |
| --- | --- | --- |
| `test.yml` | win / mac / linux 三平台矩阵跑三套 Python 测试；Ubuntu 另跑 qzone-bridge 的 typecheck + 单测 | 「我只在 Windows 上试过」是开源项目最常见的坑 |
| `secret-scan.yml` | grep 密钥 / 真实 QQ 号 / 本机路径 / Cookie 字面量 | 防止以后某次提交手滑把 config.json 带进来 |
| `install-dryrun.yml` | `install.sh --check` + `doctor.py --json` | 安装链路本身会坏（改了目录结构就坏），得有人守 |

**自己验一遍 secret-scan 真的有用**：临时造一个假 key 提交推上去，看 CI 是否变红，
然后 revert。这一步值得做，因为"永远绿的检查"等于没有检查。

## 4. 发布 Release（分发安装包）

### 4.1 版本号

用 [SemVer](https://semver.org/lang/zh-CN/)：`v1.0.0` / `v1.0.1`（修 bug）/ `v1.1.0`（加功能）。

### 4.2 打 tag 并推

```bash
# 打安装包（产物在 dist/，含 sha256）
# 版本号以 dist/ 里已有的产物为准：当前是 许杏玖-安装包-1.1.0.zip
python tools/make_dist.py --version 1.1.0

git tag -a v1.1.0 -m "v1.1.0：<本版一句话说明>"
git push origin v1.1.0
```

### 4.3 在 GitHub 建 Release

Releases → Draft a new release → 选 `v1.1.0` → 标题写版本名 → 说明里写：

```markdown
## 亮点
- 模型接口可插拔（本地 / 云端 / 自定义）
- 生图支持多后端，可走本地也可走云端

## 安装
下载下面的 `许杏玖-安装包-1.1.0.zip` 解压，双击 `install.bat`（Windows）
或 `bash install.sh`（Linux/macOS）。

校验（可选）：sha256 = <make_dist.py 打印的那串>

## 已知限制
- 除 SD WebUI / ComfyUI 外的生图后端未实测（见 docs/生图.md）
- NapCat 是 Windows 注入式的；Linux/macOS 见 docs/部署-Linux.md
```

**把 `dist/` 里的 zip 拖到 Assets 里**（这才是分发的正路；只放仓库里没人找得到）。

> `.gitignore` 已经把 `dist/*.zip` 忽略掉了 —— 二进制产物不该进版本库，
> 应该挂 Release。

## 5. 之后怎么维护

### 5.1 Issue / PR 流程

- 别人报 bug → Issue 模板会问「系统 / 版本 / 复现步骤 / `doctor --json` 的输出」；
  拿到 `doctor --json` 基本能定位一半问题；
- 收到 PR → 看 CI 绿不绿 → 看 `CONTRIBUTING.md` 里那几条（不许提交密钥、测试要过）；
- **别直接合并来路不明的 PR**：它可能改 `install.sh` 往里塞下载执行。
  改脚本类 PR 一定逐行看。

### 5.2 安全响应

`SECURITY.md` 里写了怎么私下报漏洞。收到后：
1. 先确认影响面（有没有真实密钥/账号风险）；
2. 修 + 发补丁版本；
3. 在 Release Notes 里写清 "影响版本 / 修复版本 / 用户要做什么"。

### 5.3 依赖更新

`requirements.txt` 用的是**版本下限 `>=`**，不是锁死 `==`：pillow / websockets 这类带 C 扩展的包
一旦钉死在"某个老 Python 上解析出的版本"，在更新的 Python（如 3.14）上往往没有预编译 wheel，
pip 只能回退源码编译，在没装编译器的机器上直接失败（详见 `qqbot/requirements.txt` 开头的说明）。

需要**可复现构建**时另出一份 lock，用那份装（`requirements.txt` 本身保持 `>=`）：

```bash
.venv/bin/python -m pip install -U <包名>
.venv/bin/python -m pip freeze > requirements.lock.txt    # 需要完全复现时按这份装
.venv/bin/python test_regression.py                       # 必须全绿
```

## 6. Gitee 镜像 + 国内加速

### 6.1 建镜像

Gitee → 新建仓库 → 底部选「导入已有仓库」→ 填 GitHub 地址。
之后每次推送，Gitee 会**手动**同步（或用它自带的镜像更新按钮）。

也可以自己加一个远端一次推两处：

```bash
git remote set-url --add --push origin https://github.com/<你>/xuxingjiu.git
git remote set-url --add --push origin https://gitee.com/<你>/xuxingjiu.git
git push origin main      # 一次推两个远端
```

### 6.2 国内用户装依赖慢

写进 README 的「国内加速」小节，直接给命令：

```bash
# pip
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
# 或临时用
.venv/bin/python -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

# npm
npm config set registry https://registry.npmmirror.com
```

## 7. 一些不那么显然的注意事项

1. **别在 README 里写"仅供学习，作者不负责"就完事**。这个项目涉及 QQ 空间接口逆向，
   `NOTICE.md` 里那段免责声明是必要的，但更重要的是**不要在仓库里附带任何破解/绕过工具**。
2. **Issue 里有人贴密钥时**：立刻删掉那条评论（GitHub 上你有权限），
   然后提醒他去吊销。**别只在回复里说"记得删"** —— 已经泄露了。
3. **别接受"帮我加个功能"但 PR 里塞了商业 API key**：那会让你的仓库带上别人的密钥。
4. **文档里的绝对路径**（`D:\...`、`/home/xxx`）会让别人一眼看出是"个人项目照搬"，
   提交前 grep 一遍换成相对路径。
5. **中文 commit message 没问题**，但 Issue/PR 模板建议中英双行，
   否则国际用户没法提 issue。本仓库的模板就是这么写的。
6. **不要 force push 已发布的分支**。`main` 被 force push 后，
   别人的 fork 会全部冲突。
7. **`.gitignore` 写完要验证**：`git status --ignored --short | grep '^!!'`，
   确认该忽略的都忽略了。本仓库已经内置了这份验证（见 §0.3）。

## 8. 一页速查（按顺序执行）

```bash
# ① 自查（必须全绿才继续）
bash tools/preflight.sh            # 或手工跑 §0.1 那几条 grep

# ② 建仓 & 推
git remote add origin https://github.com/<你>/xuxingjiu.git
git push -u origin main

# ③ 上 GitHub 设置分支保护 + Topics

# ④ 打安装包 + tag + Release（版本号与 dist/ 里的产物保持一致）
python tools/make_dist.py --version 1.1.0
git tag -a v1.1.0 -m "v1.1.0"
git push origin v1.1.0
# 然后到 Releases 页面建 Release 并上传 dist/*.zip

# ⑤ 给仓库加个 Gitee 镜像（可选）
```

完成标志：陌生人能**只靠 README** 在 20 分钟内把机器人跑起来。
跑不通就说明文档还有缺口 —— 这是最好的验收方式。
